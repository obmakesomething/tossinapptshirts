## 1. 서비스 개요

AI 기반 커스텀 의류(티셔츠/후드/맨투맨) 디자인 → 주문 → 결제까지 원스톱 제공.
토스 앱 내에서 실행되므로 **별도 로그인 불필요** (토스 세션 자동 연동).

### 핵심 가치
| 가치 | 설명 |
|------|------|
| **즉시성** | AI 프롬프트 한 줄로 디자인 완성 |
| **접근성** | 토스 앱 안에서 디자인부터 결제까지 |
| **품질** | Vertex AI 업스케일 + 고해상도 인쇄 파이프라인 |
| **안심** | 인쇄 품질 사전 확인, 출고일 안내, 명확한 정책 고지 |

### 설계 원칙

> 이 서비스의 본질은 "예쁘게 만드는 것"보다 **"안심하고 주문하게 만드는 것"**이다.

1. **한 화면, 한 결정** — 사용자에게 동시에 여러 결정을 요구하지 않는다
2. **신뢰 우선** — 구매 직전에 인쇄 품질, 출고일, 정책을 명확히 보여준다
3. **복구 가능** — 모든 실패 상태에서 사용자의 작업이 보존된다
4. **사용자 언어** — UI 카피는 기술 용어가 아닌 사용자가 쓰는 말로 작성한다

### 2.2 단계별 터치포인트

| 단계 | 사용자 행동 | 시스템 반응 | 실패 시나리오 | 복구 설계 |
|------|-----------|-----------|-------------|----------|
| **진입** | 토스앱에서 미니앱 실행 | 토스 세션 자동 연동, 홈 렌더링 | 세션 만료 | 토스 재로그인 유도, 편집 중 작업 로컬 보존 |

| **생성** | AI 프롬프트 입력 / 사진 업로드 | Gemini 생성 or GCS 업로드 | 생성 실패·타임아웃 | "다시 만들기" + 진행 상태 바, 30초 타임아웃 안내 |
| **생성** | 배경 제거 요청 | rembg 배경 분리 | 배경 제거 실패·부분 실패 | "원본으로 계속할까요?" 선택지 제공 |
| **생성** | 이미지 업로드 | GCS 업로드 | 용량 초과 (10MB) | "10MB 이하 이미지를 올려주세요" + 파일 선택 재시도 |
| **편집** | 위치/크기/회전 조절, 텍스트 추가 | 실시간 캔버스 반영 | — | Undo/Redo로 실수 복구 |
| **확인** | 품질 확인, 색상/사이즈 선택 | 가격 자동 계산, 인쇄 품질 배지 표시 | 저해상도 이미지 | "이미지가 흐리게 인쇄될 수 있어요" 경고 |
| **결제** | 배송지 입력 → 토스페이 | 주문서 PDF 생성, 이메일 발송 | 결제 실패 | 구체적 사유 안내 + 재시도, 주문 정보 보존 |
| **결제** | — | — | 결제 성공 + 주문 제출 실패 | 결제 취소 자동 처리, 사용자에게 명시적 안내 |
| **주문 후** | 주문 내역 확인, 배송 추적 | 상태 업데이트, 배송 정보 표시 | 배송 지연 | 예상 일정 + 문의 연결 |

## 4. CTA 구성 & 전환 전략

### 4.1 Primary CTA (주요 행동 유도)

| 위치 | CTA 텍스트 | 타입 | 목적 |
|------|-----------|------|------|
| 홈 Hero | **지금 만들어보기** | Primary Button | 핵심 전환: 홈 → 디자인 시작 |
| 디자인 시작 | **이 디자인으로 편집하기** | Primary Button | 디자인 확정 → 편집 진입 |
| 편집 Header | **완성 보기** | Text Button | 편집 완료 → 확인 단계 |
| 확인 하단 | **주문하기 ₩108,000** | Primary Button | 결제 전환 (금액 포함) |
| 주문 하단 | **토스페이로 결제하기** | Primary Button | 최종 결제 |
| 주문 완료 | **주문 상세 보기** | Primary Button | 후속 관리 진입 |

### 4.2 Secondary CTA (보조 행동)

| 위치 | CTA 텍스트 | 타입 | 목적 |
|------|-----------|------|------|
| 홈 상품카드 | 카드 탭 | Pressable Card | 상품 정보 확인 |
| 홈 하단 | 사이즈·소재·인쇄 정보 → | Text Link | 상품 상세 탐색 |
| 편집 캔버스 | ＋ | Circle Button | 사진 추가 |
| 편집 탭 | 배경 지우기 | Secondary Button | 디자인 정교화 |
| 확인 | 사이즈 가이드 → | Text Link | 사이즈 선택 도움 |
| 주문 | 주소 검색하기 | Secondary Button | 배송지 입력 |
| 주문 상세 | 배송 추적하기 | Secondary Button | 배송 현황 확인 |

### 4.3 전환 퍼널

```
홈 방문 (100%)
  ↓ "지금 만들어보기" or 상품카드 탭
```

### 5.3 상태 관리

```
context/
├── CatalogProvider    — 전역 상태 (상품/디자인/주문)
│   ├── selectedProduct, selectedColor
│   ├── orderLines[] (사이즈 × 수량)
│   ├── activeSide: 'front' | 'back'
│   ├── layers: {
│   │     front: Layer[],    ← 면별 레이어 배열
│   │     back: Layer[]
│   │   }
│   │   Layer = ImageLayer | TextLayer
│   │   ImageLayer = { type, uri, transform: {x,y,scale,rotation} }
│   │   TextLayer = { type, text, font, size, color, transform }
│   ├── selectedLayerId: string | null
│   ├── history: { past: State[], future: State[] }  ← Undo/Redo
│   ├── savedDesigns[] (서버 저장 or 명시적 로컬 + 경고)
│   └── autoSaveStatus: 'saved' | 'saving' | 'error'
├── OrderProvider      — 주문 상태
│   ├── orders[]
│   ├── activeOrder (상태 타임라인)
│   └── shippingInfo (배송 추적)
├── JobTrackerProvider — AI 생성 작업 추적
│   ├── activeJob (queued → running → succeeded/failed)
│   ├── polling (1.5초 간격)
│   └── timeout (30초, 안내 메시지)
└── ToastProvider      — 토스트 알림
    └── 오류는 토스트만이 아닌 인라인 메시지로도 표시
```

> **변경 사항**:
> - `imageTransform` (단수) → `layers` (면별 다중 레이어 배열)
> - `textLayer` (단수) → Layer 유니온 타입에 포함
> - `selectedLayerId` 추가 (선택 상태 관리)
> - `history` 추가 (Undo/Redo)
> - `OrderProvider` 신규 (주문 내역, 배송 추적)
> - `autoSaveStatus` 추가
> - `savedDesigns` 저장 정책 명확화

1. **작업 보존**: 실패가 발생해도 사용자의 편집 내용은 보존된다
2. **명확한 사유**: "오류가 발생했습니다"가 아닌 구체적 상황 설명
3. **다음 액션**: 모든 오류에 복구 가능한 다음 행동을 제시
4. **단계적 대응**: 토스트 → 인라인 메시지 → 풀스크린 (심각도에 따라)

### 13.2 오류 표시 방식

| 심각도 | 표시 방식 | 예시 |
|--------|---------|------|
| 낮음 (정보) | 토스트 (3초 자동 닫힘) | 저장 완료, 복사 완료 |
| 중간 (경고) | 인라인 메시지 + 토스트 | 인쇄 품질 경고, 용량 초과 |
| 높음 (오류) | 인라인 메시지 + 복구 버튼 | 생성 실패, 결제 실패 |
| 치명적 | 풀스크린 메시지 | 세션 만료, 네트워크 끊김 |

### 13.3 자동 복구 시나리오

| 시나리오 | 자동 동작 |
|---------|---------|
| 네트워크 재연결 | 저장 대기열 자동 재시도 |
| 앱 백그라운드 → 포그라운드 | 세션 유효성 확인, 편집 상태 복원 |
| 결제 성공 + 주문 실패 | 결제 자동 취소(환불) 처리 |
| AI 생성 타임아웃 | 30초 후 타임아웃 안내 + 대안 제시 |

## 14. 저장 정책

### 14.1 저장 방식

| 방식 | 내용 | 시점 |
|------|------|------|
| **자동 저장** | 편집 중 변경사항 자동 저장 | 편집 액션 후 3초 디바운스 |
| **서버 저장** | 토스 세션에 연동된 서버 저장 | /preview에서 명시적 저장 시 |
| **로컬 캐시** | 비정상 종료 시 복구용 임시 저장 | 주요 상태 변경마다 |

### 14.2 저장 안내 카피

- 자동 저장 시: "자동 저장됨" (상단 캡션)
- 서버 저장 시: "디자인이 저장됐어요. 다음에 이어서 편집할 수 있어요."
- 서버 저장 실패 시: "저장하지 못했어요. 네트워크를 확인하고 다시 시도해주세요."

> **원칙**: 사용자에게 "저장"은 계정에 저장을 의미. 로컬 전용 저장은 불안 요소이므로, 서버 저장을 기본으로 하되 로컬 캐시는 복구용으로만 사용.
